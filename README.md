# ДЗ 10.1. Бенчмарк: префиксные суммы против решения в лоб

Заполните этот файл и сдайте вместе с папкой `homework/`.

## Как начать

Нужен Go 1.22 или новее. Команды запускайте из этой папки, где лежит `go.mod`.

1. Реализуйте `NumArray`, `Constructor` и `SumRange` в `prefix.go`, как в LeetCode 303. `SumRangeNaive` уже готова, её не меняйте.
2. Запустите `go test ./...`. Пока `NumArray` заглушка, `TestSumRange` падает. Это нормально для стартового кода.
3. В `bench_test.go` допишите `BenchmarkSumRangePrefix`: внутри каждого повтора по `b.N` создайте `NumArray` и выполните все запросы `queries`. Подготовка данных остаётся до `b.ResetTimer()`.
4. Запустите оба бенчмарка командой ниже. Затем поменяйте только `benchN` со `100_000` на `1_000_000` и повторите замер. `benchQ` оставьте равным 1000.
5. Заполните таблицы и выводы ниже. Проверьте код: `go vet ./...`.

До реализации `NumArray` наивный бенчмарк можно запустить отдельно: `go test -run '^$' -bench SumRangeNaive -benchmem ./...`. Флаг `-run '^$'` пропускает обычные тесты.

Границы запроса включены в сумму: `0 <= left <= right < len(nums)`. Массив не пустой; проверять неверные индексы в этом задании не нужно.

## 1. Сложность

| Функция         | Время                        | Память |
|-----------------|------------------------------|--------|
| `SumRangeNaive` | O(n) проходимся по циклу     | O(1)   |
| `Constructor`   | O(n) строим префиксы в цикле | O(n)   |
| `SumRange`,     | O(1) один вызов              | O(1)   |

## 2. Цифры бенчмарка

Команда: `go test -bench SumRange -benchmem ./...`

`ns/op` означает наносекунды на один прогон всех 1000 запросов. Для префиксов сюда входит и построение `NumArray`. Это не время одного запроса. Запишите свои результаты, одинакового ускорения на всех компьютерах не будет.

| Бенчмарк                   | n = 100 000, ns/op | n = 1 000 000, ns/op |
|----------------------------|--------------------|----------------------|
| `BenchmarkSumRangeNaive`   | 6_677_543 ns/op    | 6_810_318_700 ns/op  |
| `BenchmarkSumRangePrefix`  | 72_676 ns/op       | 96_276_533 ns/op     |

## 3. Выводы

Во сколько раз префиксы быстрее при n = 100 000? Как изменилась разница, когда n выросло в 10 раз, и почему?
